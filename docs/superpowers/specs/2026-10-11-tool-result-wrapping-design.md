# Tool-result wrapping and approval gates

Add general policy capabilities; do not hardcode confidentiality categories or warning text in runtime code.

Policies may target the current `tool_result`, rather than a response or historical results, and request `delivery: wrap`. On a violation the policy's Correction text surrounds the tool's textual content. On an inconclusive/unavailable review the wrapper says the review is incomplete and includes the same policy instruction. Clear results remain unchanged. Observe mode never changes content. Preserve the host's structured output schema, metadata and non-text blocks. Unsupported host/result shapes receive explicit additional context rather than an invalid replacement. Each result is independent of response correction limits.

Add `on_failure: block` for pre-tool policies. An unknown/unavailable/missing review, truncated evidence, stale review or unavailable state denies an eligible call instead of failing open. Defaults remain unchanged for existing policies. Add `include_evidence: false` for feedback that should not repeat captured source text. These are independent policy controls, validated by the catalog.

Claude delivery uses `PostToolUse.updatedToolOutput`, with a shape-preserving wrapper. Read text keeps its file metadata, Bash keeps its stdout/stderr/boolean schema, and MCP blocks get warning text around the original blocks. The wrapper uses a fresh boundary so content cannot close its own enclosing delimiter. Other hosts must not receive unsupported replacement fields: use additional context where replacement is unavailable. Document host differences and that this intentionally leaves original content available to the model, remote reviewer and local journal. A crashed/timed-out PostToolUse hook can still leave the original result without its wrapper: incoming warnings are best-effort and the independent pre-tool gate is the enforcement boundary.
