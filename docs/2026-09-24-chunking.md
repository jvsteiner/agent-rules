# Bounded evidence chunking

Oversized reviews now use additional Jev requests rather than automatically
skipping every oversized task. Small questions retain the normal shared batch.
Overflow tasks are planned into overlapping evidence windows, with a default
limit of four requests per review, configurable from one to eight through
`maxReviewRequests`. At most two requests run concurrently. All share the same
`reviewDeadlineMs` deadline; there are no retries.

Each serialized request stays below the plugin's 24,000-character budget,
including questions and coverage metadata. This is an operating budget, not the
vendor limit: [TypeSafe's model documentation](https://docs.typesafe.ai/models)
specifies 64k total tokens and 32k for state plus the longest question.

Long response, candidate, receipt input/output, change text/context, and exposed
thinking fields use 256-character overlaps. Short context and record metadata
remain intact. Each request explicitly tells the model that evidence is excerpted;
source offsets, chunk index/count, and the raw judgments are retained. Unsupported
large fixed context, oversized questions, and plans exceeding the request cap
remain unknown. This does not promise arbitrarily large input coverage.

Generic aggregation requires complete, unanimous clear or violation judgments.
Mixed results and unknowns abstain; missing chunks after a failed request or
deadline cannot become clear. Probabilities are not averaged. This deliberately
means a local violation in one excerpt with clear judgments elsewhere remains
inconclusive; rule-specific existential aggregation is not implemented.

Runtime capture now preserves up to 96,000 characters per evidence string and
limits text in review snapshots to 512,000 characters. Truncation and rolling
collection eviction are labeled. Incomplete sources affect only policies that
depend on them, so a clipped receipt does not suppress an independent response
check. Journals retain bounded chunk judgments and explicit history truncation.

## Validation

- `npm test`: **134 passing**, zero failures or skips; bundles rebuilt.
- Regressions cover long-response tails, multiple large receipts, source offsets,
  preserved short context, conflicting judgments, request budgets, later request
  failure, shared deadlines, capture truncation, and runtime-to-review integration.
- One live Jev 1.13.0 regression evaluated a 29,900-character synthetic response in
  three requests, each below 24,000 characters. All three classified the repeated
  explicit cat-picture content as a violation. Usage was 16,448 input tokens and
  135 output tokens. This check used a five-second deadline; it demonstrates
  chunked classification, not a latency guarantee under the default two seconds.
- No full coding-agent session was needed for this change. Host hook behavior was
  already verified; the new tests exercise the shared runtime and reviewer path.
